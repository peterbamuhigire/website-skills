## 5 Whys for the critical defect (WSK2-D1)

1. Why did the security gate print `high=0 critical=0` with no lockfile? Because the counts came from `jq` run over an error document that has no `vulnerabilities` key.
2. Why was an error document parsed as a result? Because `npm audit` was allowed to fail (`|| AUDIT_EXIT=$?`) and the exit status was then never read.
3. Why was failure tolerated? Because `npm audit --audit-level=high` also exits non-zero when it finds vulnerabilities, and the author wanted to read the counts either way. The two meanings of "non-zero" were not separated.
4. Why was it not caught? The gate fixtures in `tests/gates/` are canned JSON reports, not executions of `security-gate.sh`; nothing runs the shell script with a failing `npm`.
5. Why was there no such test? The 29 October cycle exercised the gate only through a real lockfile with real findings, so only the "findings found" path was ever seen. Root cause: **proof and tooling**, a gate with one tested branch.
