# Website Agency Engine Roadmap

This roadmap turns the current repository from a strong portable skill library into a complete
website development engine for a premium agency that can consistently deliver $10k+ websites
and earn the position of best-in-class web design practice in Africa.

The plan is grounded in the analysis at `docs/evaluation/2026-04-12/`, which scored the system
at **8.5/10** and identified enforcement, visual QA, automation, multi-operator proof, and
continental authority as the remaining gaps between the current state and a true world-class
agency engine.

## Why This Plan Exists

The 2026-04-12 evaluation makes three things clear:

1. The repository already has strong website, SEO, UX, copy, design, commercial, strategy,
   delivery, governance, and authority coverage (Phases 1-9 closed those gaps).
2. The remaining weaknesses are no longer about missing thought; they are about missing
   enforcement, visual QA, automation, proof of governance under multi-operator load, and
   public continental authority.
3. A world-class agency engine needs more than skills. It needs hard validation gates,
   automated CI, observable metrics, certified operators, and demonstrated leadership in
   the African web design market.

## Operating Principle

Each phase must produce assets that the next phase can consume. Do not treat phases as abstract
study blocks. Each one should leave the repository, templates, scripts, checklists, gates, or
public artifacts in a stronger state.

## Target End State

At the end of Phase 12, this repository should support an agency model with:

- a clear premium market position recognised across the African continent
- defined client qualification, proposal, and proof logic
- repeatable strategy, build, conversion, and SEO workflows
- hard, machine-enforced gates for performance, accessibility, visual quality, security, and metadata
- one canonical CI pipeline that runs every gate on every change
- live observability connecting client outcomes to repository evolution
- a working experimentation programme that produces evidence rather than opinion
- multi-operator certification proven through timed onboarding, not assumed
- an open-source benchmark library and case-study corpus that establish public authority
- reading material, training, and a knowledge commons that another operator can absorb in weeks

That is the difference between a useful skill library and the African continent's leading
website development engine.

## How To Use This Plan

Operators executing the plan should:

- read the [Executive Summary](./executive-summary.md) before touching any phase
- read each phase document end-to-end before starting work in it
- treat the **Repository Outputs Required** section as the acceptance contract for the phase
- record every decision in `project-log/decisions/` per the project-log standard
- update [Success Metrics](./success-metrics.md) at the end of each phase
- only mark a phase complete when the named outputs exist and the success criteria are observably met
