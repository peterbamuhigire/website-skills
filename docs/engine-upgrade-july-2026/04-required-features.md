# Required Features for World-Class Output

1. A manifest-backed router with generated indexes, relocation aliases, dependency graph, and link validation.
2. A project delivery contract covering discovery, content, design, build, SEO, release, observability, and post-launch learning.
3. Three runnable benchmark projects: East African B2B services, multilingual local business, and retail commerce; each must include a brief, source assets, completed pages, tests, reports, and handover.
4. Deterministic CI that installs from any resolved engine location, pins tool versions, validates runner paths, uses least-privilege GitHub permissions, and produces structured reports.
5. Gate fixture suites for performance, visual regression, accessibility, security, metadata, drift, and design-quality scoring, including intentional failing cases.
6. A design-quality review system with named reviewer roles, calibration samples, accessibility/visual conflict resolution, and a decision log.
7. Native-language QA workflow: translator/writer identity, regional variant, reviewer checklist, localized SEO intent, locale screenshot and link checks.
8. A compliance boundary: standards register, jurisdiction applicability matrix, legal-review trigger, consent/analytics checklist, and disclosure templates.
9. An asset and evidence library: approved photography/illustration guidance, content source register, proof-claim verification, testimonial consent, and case-study permissions.
10. A release/handover pack: owner training, credentials/ownership transfer checklist, monitoring dashboard, incident/rollback contacts, maintenance and experiment backlog.

Anti-slop governance must be measurable: banned patterns, typography and image provenance, content-specificity test, duplicate-component test, token-conformance lint, and human visual review. It must reference the external design-system engine through a verified interface rather than an informal path mention.
