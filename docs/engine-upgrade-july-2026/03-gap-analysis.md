# Gap Analysis — Path from 65 to 95+

## Richness

Move from broad guidance to an evidence-backed knowledge product. Each skill needs a minimum reference standard: authoritative sources, applicability notes, a decision tree, one ordinary example, one difficult case, and a completed output. Build vertical packs for legal, health, finance, education, hospitality, public sector, nonprofit, and commerce; do not leave sector routing to an external engine without a durable handoff.

## Robustness

Make the operating contract executable. The installer must accept a resolved engine path, generate a project-local immutable manifest, verify the copied CI paths, and fail fast when a required runner is missing. Every gate needs pass/fail fixtures, deterministic command contracts, report schema, timeout policy, waiver record, and a known limitations section. Add Windows developer ergonomics or clearly support WSL/CI only.

## World-class output

Define “done” as a client-ready evidence pack: approved discovery and content source register; reusable tokens/components; localized copy approved by native reviewers; rendered desktop/mobile screenshots; axe/manual/screen-reader evidence; performance and security reports; SEO validation; consent-aware analytics; training/handover; and a 30-day learning plan. Add external design critique and editorial review rather than self-scoring only.

## Architecture

Retire prose-only routing. The manifest should declare skill id, owner, status, aliases, dependencies, inputs, outputs, required references, required external engines, safety level, and last verified date. Generate all indexes from it. Replace every active reference to relocated skills with either an explicit external-engine route or an in-repo successor; keep historic plans as historical but label them.

## Composability

Standardise project artifacts (`strategy-brief`, `content-inventory`, `route-map`, `design-tokens`, `measurement-plan`, `release-evidence`) with lightweight schemas and example files. Each downstream skill should name an input version and output version. Provide starter and advanced fixture projects so integration is tested, not inferred.

## Currency and compliance

Create a controlled standards register and jurisdictional boundaries. Track W3C/WCAG, Google Search Central, schema.org, RFC 9116, OWASP ASVS/Top 10, GDPR/ePrivacy, local data-protection and consumer rules, and payment/mobile-money provider terms. A named maintainer must review each source at a defined cadence and record decisions.
