# Mobile And Dashboard Website Patterns

This reference is self-contained. It distills the user's supplied Design Studio UI/UX
mobile navigation, mobile onboarding, dashboard, and mobile app examples articles for
website and web-product delivery.

## Website Mobile Navigation

- Keep mobile primary navigation focused on the buyer's top jobs: understand offer,
  inspect proof, choose service/product, contact/apply/book, and access account or help.
- Do not hide the primary conversion action deep inside a hamburger menu.
- Use a sticky bottom CTA only when it does not cover content, forms, chat, or browser UI.
- Keep tap targets generous, labels short, and active location obvious.
- For content-heavy enterprise sites, combine a simple mobile menu with search and clear
  page-level section anchors.

## Website Onboarding Analogy

Marketing websites do not have app onboarding, but first visits still need a guided first
value path.

- The first viewport should prove category, promise, credibility, and next action.
- Do not ask for email, account creation, or long forms before the visitor understands
  value.
- Use progressive disclosure for complex services: summary first, details and proof on
  demand.
- For portals, dashboards, ecommerce accounts, or SaaS marketing sites, route the product
  onboarding requirements back to the SRS engine before implementation.

## Dashboard And Proof Presentation

Use dashboard thinking when presenting business proof, case-study numbers, analytics
snapshots, donor reporting, internal portals, or admin screens.

- Every metric block needs context: target, trend, prior period, benchmark, or action.
- Show source and date for claims, case-study figures, and reporting dashboards.
- Prioritize exception, risk, or opportunity before decorative overview cards.
- Use direct labels and readable tables when exact comparison matters.
- Avoid decorative gauges, 3D charts, unlabelled axes, disconnected legends, and metrics
  with no buyer decision attached.

## Mobile Quality Gate

Before visual QA, confirm:

- Mobile navigation exposes the conversion path in one or two taps.
- Mobile forms explain effort, next step, and expected response time.
- Proof appears close to high-friction decisions.
- Media loads fast and does not push core content below the fold unnecessarily.
- Sticky UI does not overlap text, buttons, cookie notices, chat widgets, or browser chrome.
- Dashboard/proof metrics have labels, source, date, and action relevance.
