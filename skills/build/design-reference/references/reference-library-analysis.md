# Reference-library analysis

Use this worksheet when the supplied inspiration is a PDF, image collection,
screenshot set, or saved page rather than a live URL. Treat it as a visual pattern
library, not as permission to reproduce layouts, copy, assets, or brand identity.

| Field | Record |
|---|---|
| Source record | File, page/figure or capture ID, date supplied, completeness and rights status |
| Observation | What is visibly present; separate this from inference |
| Audience job | What user task or decision the pattern appears to support |
| Pattern abstraction | Layout, hierarchy, proof placement, navigation, interaction, typography, colour, imagery, or responsive idea |
| Decision | Adopt, adapt, reject, or unassessed |
| Fit checks | Brand, content, accessibility, performance, responsive, localisation, privacy, and implementation constraints |
| Handoff | Design-system token/component/pattern or page-builder implication, owner, and acceptance evidence |

For a book or catalogue, analyse representative pages and record page locators;
do not transcribe captions or recreate distinctive compositions. The downstream
design-system must receive principles and constraints, not a copied mood board.
