# Signup Human Validation

Parent skill: [page-builder](../SKILL.md). Read when a website form creates an account or initiates a signup-related email.

Use Cloudflare Turnstile in Managed mode as the default human-verification step on web signup forms to help reduce bot-driven and other unauthorised automated use. The server must verify each submitted token through Cloudflare Siteverify and check the expected hostname; a rendered widget or client-side token alone does not protect the endpoint. Treat tokens as single-use and short-lived, and request a fresh token when validation fails.

Protect resend and other signup-related message endpoints as well as the registration form. Keep independent rate limits and email confirmation. Keep the Turnstile secret server-side, restrict the widget to owned hostnames, and use separate credentials by environment. During a confirmed Siteverify outage, permit a pending signup only under stricter rate limits and mandatory email confirmation, and alert the operator; do not record the request as verified. Invalid, expired, or replayed tokens remain failures.

Make the challenge keyboard and screen-reader accessible, preserve the form data on retry, explain the next action in plain language, and test on supported mobile browsers. For native Android apps, use Firebase App Check with the Play Integrity provider and offer Turnstile in a WebView when the expected attestation is unavailable. The backend must verify the App Check token. See the [Firebase Play Integrity provider guide](https://firebase.google.com/docs/app-check/android/play-integrity-provider/) and [custom-backend verification guide](https://firebase.google.com/docs/app-check/custom-resource-backend/).

Provider facts checked 1 November 2026. Cloudflare's [server-side validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) (updated 16 September 2026) says Siteverify is mandatory and tokens are single-use with a five-minute lifetime. Its [mobile implementation guide](https://developers.cloudflare.com/turnstile/get-started/mobile-implementation/) (updated 5 May 2026) describes WebView requirements. Firebase's [Play Integrity guide](https://firebase.google.com/docs/app-check/android/play-integrity-provider/) (updated 28 October 2026) and [custom-backend verification guide](https://firebase.google.com/docs/app-check/custom-resource-backend/) (updated 6 October 2026) describe the Android provider and server-side verification. Review these details by 1 February 2027 or before implementation if provider documentation changes.
