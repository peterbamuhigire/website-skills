# Book-driven Kaizen Wave 3: website application

Use this reference for websites, landing pages, dashboards, portals, and web products.
It records durable transfer from the 18-book study; it is not a source of current APIs.

Owning skill: [Kaizen owner](../SKILL.md).

## Transfer controls

- Define page purpose, audience, primary task, information hierarchy, and next action before
  choosing layout or adding content. Show summaries, comparisons, exceptions, and context.
- Design experiments with an outcome metric, guardrails, exposure/eligibility rules, and a
  rollback. Use bandits only when current evidence and operational constraints justify them;
  retain A/B or staged alternatives where attribution is clearer.
- Treat retrieval and local SEO as evidence work: entity consistency, intent fit, truthful
  structured data, useful content, and a measurable conversion path. Never promise ranking.
- Validate HTTP semantics, cache behavior, image sampling/quality, responsive rendering,
  accessibility, performance, security, and graceful AI fallback with rendered or runtime
  evidence.

## Boundaries

Historical dashboard, IR, image, HTTP, JavaScript, SEO, and agent examples require current
verification. Do not copy legacy protocol or browser assumptions, unsafe client/server code,
or unverified platform claims. Mark absent analytics, renders, or external-policy evidence
`NOT_ASSESSED`.

## Measures and routing

Track task completion, qualified conversion, abandonment, accessibility defects, Core Web
Vitals or current performance measures, search/indexing evidence, retrieval quality, image
quality, experiment uncertainty, and rollback success. Route to design-system, SEO/content,
analytics, security, and launch gates.

## Currentness gate

Verify current web protocol guidance against RFC 9110/9114, accessibility against WCAG 2.2
and WAI guidance, and search claims against Google Search Essentials and applicable policies.
Record source, date, freshness, support, uncertainty, and recheck trigger.
